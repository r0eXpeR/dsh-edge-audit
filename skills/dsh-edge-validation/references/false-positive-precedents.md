# 误报先例

## 使用方式

下列条目是**默认假设，须被具体源码证据推翻**，不是关键词删除规则。不得因候选标题、类别、文件后缀或路径命中某条就删除。

- 处理顺序：先找反证；默认假设成立且无推翻证据时才判 suppressed/not_applicable，并写明依据的具体源码，而不是只引用本文件。
- 默认假设被推翻时，继续走 proof tuple，不因属于“低信号类别”压低结论。
- 证据缺失本身不证明安全。默认假设依赖的事实未知且决定结论时，记 deferred，不写成反证。
- 上游以这些规则直接排除；本项目保留判定权，以下每条都写明推翻所需证据。

## 与上游的有意差异

- **DoS、资源耗尽、内存/CPU、rate limit、资源泄漏**：上游直接排除，本项目保留这些类别（见 resources）。成立条件是证明攻击者成本放大：小输入造成超线性或持久的共享影响、认证前工作失衡、跨租户影响、运营方花费放大。泛化的“缺 rate limit”“可能泄漏”“无限循环”仍不算。
- **Open redirect、XS-Leaks、prototype pollution、tabnabbing**：上游排除；本项目默认低信号，能证明 client、web-auth 参考要求的完整条件（gadget、机密 predicate、重定向造成的凭据泄露等）时保留。
- **Regex injection/ReDoS**：按 resources 的超线性复杂度验证，不按关键词排除。
- **Markdown 等文档文件**：上游排除；本项目中文档里的真实凭据仍按 source-disclosure 判定。
- **存于磁盘的 secret**：上游交由其他流程；本项目审查嵌入凭据，需证明用途和额外权限。
- **依赖**：上游不看过期第三方库；本项目需要可达路径，见 supply-chain。

## 默认假设与推翻证据

**标识符与环境**
- UUID 和随机 ID 默认不可猜。推翻：证明攻击者能实际获取该值（列表接口、日志、URL 泄露、可预测生成器），且仍缺授权。
- 环境变量和 CLI 参数默认可信。推翻：源码证明低信任来源可写（Web 请求落入 env、不可信配置、CI 输入、跨权限的子进程环境）。
- 普通输入校验缺失、非安全关键字段默认不算。推翻：证明校验缺失带来具体安全后果。

**客户端**
- 客户端代码缺鉴权默认不算，服务端负责校验。推翻：引用对应服务端入口，证明服务端同样缺失。
- 客户端发送不可信数据到后端同理，由后端验证。推翻：证明后端未校验。
- React/Angular 默认防 XSS。推翻：存在 `dangerouslySetInnerHTML`、`bypassSecurityTrust*` 或同类不安全方法，且不可信数据到达。
- 客户端 JS/TS 中的 SSRF 和路径穿越默认不成立。推翻：证明代码实际运行在服务端（SSR、Node、edge function）。HTML 文件中的 SSRF 同理。

**日志**
- 日志只有泄露 secret、密码、凭据、PII 才算；非 PII 敏感数据不算。记录请求 header 默认危险（常含凭据），记录 URL 默认安全，除非证明 URL 携带 token 或 PII。
- 把未净化用户输入写入日志（log spoofing）默认不算。推翻：证明下游解析日志并作安全决策。
- 日志查询注入默认不算。推翻：注入确定向外部用户暴露敏感数据。
- 审计日志缺失或被修改默认不算。推翻：产品明确承诺审计完整性，且低信任者能破坏它。

**文件类型**
- 仅测试文件、仅测试运行时使用的文件默认不报告。推翻：证明可被生产引用、已发布，或含真实凭据。测试文件名本身不足以作为凭据的反证。
- Notebook（`*.ipynb`）默认不可利用。推翻：具体攻击路径和低信任输入。
- GitHub Action workflow 默认不可利用。推翻：具体攻击路径，写出触发事件、可控字段、消费位置、获得的权限（见 supply-chain）。
- Shell 脚本命令注入默认不成立。推翻：具体路径证明不可信输入确实到达脚本。

**服务端请求**
- SSRF 只控制 path 默认不算。推翻：证明可控制 host 或协议，或 path 可造成具体越权（重定向跟随、内部代理路径）。
- HTTP 请求中的 `../` 默认无害。推翻：下游把它用于文件读取或路由穿越，且有具体影响。

**加固与缺陷**
- 缺加固项默认不算：代码不必实现全部最佳实践。推翻：现实路径造成跨边界影响。
- 纯崩溃默认不算（undefined、null 解引用）。推翻：证明共享可用性影响或完整性影响。
- 单纯缺 rate limit 不算；竞态和 timing 攻击只有实际可利用才算。推翻：给出可达窗口和具体业务或安全结果。
- 内存安全类仅适用于 C/C++/Objective-C、`unsafe`、FFI 或其他 native 边界。安全 Rust、托管语言默认不成立。推翻：指出具体 unsafe 或 native 代码。
- 依赖内部私有库默认不算。推翻：证明解析可落到攻击者控制的 namespace。

**AI**
- 用户内容进入 prompt 默认不算。推翻：证明 ai-agent 参考中的代码层边界失效。

## 置信度指南

评估完整发现，包括可达性、被破坏的边界、影响、反证。DSH 只用三级；括号内是上游两套互不等价的数值尺度（prompts.py 0-1、过滤器 1-10），仅作对照：

- **high（0.9-1.0，10 分制 7-10）**：路径和安全影响已确立，无重大未决反证。静态证据确立完整主张时可为 high。
- **medium（0.7-0.9，10 分制 4-6）**：直接证据支持主张，但某个实质前提或路径局部不确定，需调查。
- **low（低于 0.7，10 分制 1-3）**：支撑间接或缺重要上下文，很可能是误报或噪声。上游低于 0.7 不报告；本项目保留为 Needs Validation 或记录否决依据，不作为确认发现。

信号质量四问：有无具体可利用路径？是真实风险还是理论最佳实践？有无具体代码位置和复现步骤？安全团队能否据此行动？

Crash PoC 只证明观察到的崩溃，不证明全部声称后果。置信度与严重度分开：证据不足影响置信度，不是压低严重度的理由。
